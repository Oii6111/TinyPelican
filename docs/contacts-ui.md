# 联系人界面使用与开发说明

## 布局与视觉

联系人页保留「联系人列表 → 聊天记录 → 联系人画像」的三栏工作流，采用暖白背景、浅金色消息气泡、细分隔线和统一线性图标。所有位置均不展示头像，通过姓名、对齐和留白区分信息。

宽屏下聊天记录与画像并排显示；联系人工作区宽度不超过 1000px 时，画像改为右侧浮层，关闭后可继续查看聊天。此断点按工作区宽度计算，包含应用主导航时也能正确适配。

## 查看与导出聊天

1. 点击联系人，加载最近一页聊天记录。顶部显示联系人姓名和消息数量。
2. 聊天按本地日期分组；同一发送者连续发言时，间隔不足五分钟的消息省略重复时间戳。鼠标悬停在已显示的时间上可查看完整时间。
3. 「全部日期」下拉框只列出已加载记录中的日期；筛选不会触发全量历史查询。
4. 「查看更多聊天记录」依次读取在线历史页和归档，向前补充内容并尽量保持滚动位置。
5. 「导出记录」将当前加载且符合日期筛选的消息保存为 UTF-8 文本，包括时间、发送者和内容。导出文件名中的非法字符会被替换。

底部始终是只读提示，不提供发送消息的输入框。只有图片占位内容而没有原图时，显示「原图暂不可用」，不以示意图片冒充聊天原图。

## 查看和维护画像

- 点击顶部「画像」开关打开或收起侧栏，不重新加载消息，保持聊天滚动位置。
- 「具体画像」默认展示已保存的字段；点击「编辑」后可按分类修改，每行使用「字段：值」。备注也可编辑。
- 「保存画像」采用完整替换模式保存编辑结果。清空已有字段并保存会移除对应值。
- 「聊天话题总结」直接展示服务端返回的摘要、话题及覆盖范围；不存在摘要时展示未生成提示。
- 「更新分析」和总结卡片的刷新按钮请求更新聊天总结；「更新联系人画像」请求生成画像候选，两项操作互相独立。
- 分析状态区分未生成、生成中、已完成、失败和画像待确认，不将待审核候选直接当作已保存画像。画像候选仍需通过既有待确认流程审核。
- 画像置信度、来源和更新时间来自已有画像元数据，仅在对应数据存在时显示。
- 「清空聊天记录」和「删除联系人」独立放在数据管理区，各自保留确认与失败反馈。

## 代码入口

| 文件 | 职责 |
| --- | --- |
| `dashboard/src/views/contacts.mjs` | 联系人选择、消息分页、日期分组与筛选、文本导出、画像展示与编辑 |
| `dashboard/src/components/contact-memory.mjs` | 总结内容、分析任务状态、轮询生命周期及更新操作 |
| `dashboard/src/components/contact-visuals.mjs` | 统一线性图标与带图标按钮 |
| `dashboard/src/contact-workspace.css` | 联系人工作区专用样式及容器断点 |
| `dashboard/index.html` | 加载工作区样式 |
| `tests/contacts-ui.test.js` | 保存语义、分页与筛选、导出、请求竞态及真实状态展示回归测试 |

样式主要限定在 `.contact-workspace` 内，避免覆盖其他聊天页面。快速切换联系人或隐藏页面时，通过请求版本校验忽略过期结果，并停止画像状态轮询。

## 验证

```powershell
node --test tests/contacts-ui.test.js tests/contact-profile.test.js
npm run check
```

浏览器验证建议覆盖：宽屏并排布局、窄屏画像浮层、关闭画像后继续浏览、编辑保存、日期筛选、加载历史、文本导出，以及无头像和无横向溢出。
