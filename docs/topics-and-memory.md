# 新话题与聊天记忆

“开始新话题”只展开四个方向，选择后才生成。默认快速模式；换一批和思考模式保留当前方向，新复制聊天恢复普通回复。

- 随便聊聊：轻松选择、观点交换、求推荐、想象情境、共同计划。
- 聊点新鲜的：按宽泛兴趣搜索近七天内容，卡片独立显示可查看来源，未知发布时间不会显示为今天发生。
- 更了解对方：结合可选参考模板找了解方向，核对自由画像和已有聊天，排除已知、拒绝透露、暂不询问的事项。个人关系不默认询问商务字段。
- 回顾历史：从之前聊过的事情和未完成计划寻找联系理由。

## 配置

渠道 → 联网搜索 → 配置，或设置 → 联网搜索：启用后填写 SearXNG 地址，实例需允许 JSON 搜索格式。也可配置支持 `$web_search` 的 Kimi 模型、API 地址和密钥，将 Kimi 设为主服务或备用服务。测试使用已保存配置，保存引起核心重启时需稍等。相同查询缓存十五分钟；没有后台热点抓取任务。

快速和思考回复使用当前选定模型。快速明确关闭思考，不带人设或累计总结；思考开启模型思考并读取最新保存的画像、人设和累计总结，仍以短消息为目标。DeepSeek、SiliconFlow、Ollama 有内置适配；自定义兼容服务可设置开关 JSON。是否支持思考还取决于选用的具体模型；不支持时会显示错误。背景总结优先使用 `engine.smallModel`，否则使用当前模型。

## 总结与候选

数据库真正插入新消息时登记持久化任务，后台一次处理一位联系人，每批约 12,000 字、最多 300 条；单条超长消息独立处理以保留原文。无三十分钟静默等待。首次启用自动分页补齐热库和冷库。新联系人录入优先于旧历史补齐，重启恢复未完成任务。失败保留旧总结，最多尝试三次，再由联系人页手动重试。

总结以“日期或日期范围｜话题名称：宏观交流概述”呈现双方交流的话题时间线，避免逐句复述、具体琐事及行动清单；无依据的日期标为“时间未明确”。总体概览不超过80字，累计控制在约1,200字、二十个话题内，并记录覆盖时间与消息数。处理过程中新增的消息留在下一轮。联系人画像面板提供状态、重建总结和完整历史画像分析；已有总结可点击“立即生成 / 重建总结”按新格式重新生成。

设置 → 聊天总结与画像更新，可关闭自动画像候选，或选择每 7 / 30 天、仅特别关心 / 所有联系人。只有发生新消息变化才生成周期候选；周期以首次录入或最近一次画像分析完成时间起算。总结任务不受此开关影响。候选仅提取有联系人原话依据的信息，经待确认列表审核后按板块内字段合并，拒绝则不修改画像。

画像提取只读取发送者与联系人昵称、备注、平台标识或历史名称匹配的消息，并排除设置中的本人昵称；未知发送者不作为联系人。模型还需区分消息是在描述本人、用户还是第三人，不把朋友的经历写成联系人属性。画像字段只保留简短结论，例如“职业/学业：学生/医学方向/实习中”，通常5至30字、最多60字；聊天原文和发言时间仅保留在待确认候选的独立依据中。旧画像的内容不作为新提取的事实来源。已有画像不会自动改写，需要重新分析完整历史并审核新候选；请先在设置中配置正确的本人昵称。

参考模板仅供系统提取画像及寻找了解方向，不在联系人界面展示。空白字段不自动存入画像，没有完成率。用户自己的“社交目的及策略”不作为向对方提问的目标。

联系人面板中的具体画像、各画像板块和聊天话题总结可以折叠。保存画像、生成/重建总结、分析完整历史生成画像、清空聊天和删除联系人集中在操作区。手工保存以编辑区完整内容替换画像，可删除字段或清空板块；待确认候选仍按字段合并，避免覆盖其他手工内容。清空社交目的时同时清空对应保存值。

数据库采用增量建表和列添加，保留既有数据。归档按联系人存放在应用数据目录的 `archives/contacts`；完整历史通过分页读取，普通建议使用近期上下文。此次开发无需打包，重启开发核心和 Electron 窗口以加载新模块。
