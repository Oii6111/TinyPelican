# 今日行动推荐（泛社交）

首页的「今日行动」为每位联系人提供一至两条建议，覆盖接续聊天、新话题、邀约、具体关心、沟通修复和留出空间。产品口径是**社交关系维护**：只看用户自己写下的**社交目的**和客观聊天事实，不做情感画像、不做对人的心理分析、不提供教练式长期对话。

目录：`core/social/`（`daily-actions.js`、`goal-interval.js`、`cadence.js`、`daily-action-plan.js`）。

## 每天一份

以运行应用的设备本地日期为准，当天首次进入首页时补齐尚未生成的推荐。结果和反馈保存在现有 SQLite 数据库中，刷新页面或重启应用不会重复生成。各联系人串行生成，部分失败不影响其他联系人。

重启时还没开始跑的批次会被丢弃并在当天重新排队，用户不会看到报错；只有真正被中断的那一批会提示重试。

聊天、社交目的和日程有变化时，卡片提示有新资料，已有建议保持稳定。点击「更新推荐」才按最新资料重新分析；当天新加入的联系人会单独补齐推荐。模型错误可以手动重试，不会通过首页轮询反复调用模型。

「完成」仅代表用户做过该行动，不代表对方积极回应；「今日忽略」仅表示今天不采用。两种状态均可以撤销，也会作为后续推荐的参考。生成建议或计划都不会向联系人发送消息。

## 谁能进今日行动

只有真正的「人」才会收到行动建议：

- `kind='contact'`（联系人）：进入今日行动。
- `kind='group'`（群）：不是人，不生成。
- `kind='member'`（群里出现过、还没加联系人）：不生成。
- `inbox`、名字含「未归属」的占位记录、以及配置里的本人昵称：不生成。

## 间隔怎么定

今日行动多久生成一次，由**社交目的给出基准**、再用**客观信号修正**。两层都不看模型推断出来的描述性状态。

**基准**从社交目的的文字推导，确定性规则、不调模型：

| 社交目的里表达了 | 基准间隔 |
| --- | --- |
| 推进：约见面、约一次、邀请、拜访、推进、尽快、主动联系 | 每天 |
| 了解：了解、熟悉、慢慢、先聊、观察、认识 | 约每两天 |
| 维持：维持、保持、老朋友、家人、偶尔、不定期、日常问候 | 约每周 |
| 暂停：暂停、先放一放、冷处理、不想联系 | 不主动生成 |
| 没填社交目的 | 不生成（先填社交目的） |

**修正**只看客观事实：

| 信号 | 系数 | 怎么看 |
| --- | --- | --- |
| 对方最后一句还没回 | ×0.5 | 最后一条消息不是用户发的 |
| 最近采纳过建议 | ×0.8 | 近 7 天有「完成」 |
| 最近聊得很勤 | ×1.5 | 近 7 天消息 ≥ 20 条 |
| 最近连续忽略建议 | ×1.5 | 近 7 天忽略 ≥ 2 且没有完成 |
| 已经很久没聊 | ×2 | 距上次对话 ≥ 14 天 |

最终间隔 = 基准 × 各系数，夹在 1–30 天之间。首页显示成「间隔：了解 2 天→约每 1 天一次（对方最后一句还没回）」，用户能看出系统为什么这么排。

模型也可以在同一次生成里判一个更合适的天数（1–30），服务端再套护栏：夹进 1–30 天、单次变动不超过上一版的 2 倍；被夹过会写进决策日志并在卡片上说明。

**没填社交目的的联系人不生成今日行动**，只收在「推荐设置与依据」里，提供填写入口。没有目的就没有判断依据，先生成只会变成套话。填完之后该联系人从下一天起按目的安排节奏。

**画像、模型推断出来的关系描述都不参与这个判断。** 它们喂回调度会形成自我印证的闭环，也会让用户没法通过改社交目的来控制系统行为。这些资料仍可作为语境交给模型理解联系人，但不决定要不要生成、多久生成。

**日程优先**：未来 3 天内有明确关联联系人的日程时，无论间隔算出来是多少都会照常生成——「明天是爸爸生日」不能因为「前天刚聊过」而漏掉。

按间隔跳过的那一天会写入一条 `resting` 记录并说明原因，前端显示成「今天先不动」，不会当成待生成反复重试。同一天里再次生成、或者用户手动点「更新推荐」，都会绕过间隔。

## 今天不必行动

除了节奏之外，模型本身也可以判断今天不适合推进：刚聊完、对方说过需要空间、上次话题还没接上时，会返回空建议并把 `resting` 设为 true，用一句话说明为什么先不动。这与「资料不足」区分开——后者说明缺什么资料，前者说明今天不该动。

## 依据与策略

推荐使用联系人资料里的社交目的、近期聊天原文、历史摘要、聊天预览的覆盖范围、明确关联联系人的日程及近期行动反馈。没有填写目的时，建议保留探索性，并提供填写入口。

间隔信息会先算好再交给模型：距上次对话几天、最后一句是谁说的、本段预览覆盖了多少条。**间隔只用来判断行动时机，不用来推断对方态度**——可以说「上次聊是 11 月 12 日，停在看展」，不能把「三天没回」读成冷淡、拒绝或关系降温，也不推导「对方应该多久回一次」的标准。

聊天原文是有范围的预览，保留发送者、时间、覆盖范围和截断信息。没有新导入记录不表示没有联系。用户自己整理的资料只是可修正线索，不是对人的诊断。日程没有明确联系人归属时，不按标题猜测。

推荐和详细计划共享策略规则：准确回应情绪、关注对方分享的具体内容、渐进且互惠的自我披露、清晰且方便拒绝的邀约、可兑现的支持、冲突修复和尊重边界。这些原则不能保证关系结果，也不支持激将、制造嫉妒、虚构经历或惩罚性冷落。

模型必须返回结构化建议并引用本次输入中的依据编号。服务端校验编号并回填资料原文，不接受模型自行编写的引用。「推荐依据」可在首页展开查看。

## 详细行动

点击「查看详细计划」会按需生成 3–5 个可执行步骤，包含适合的时机、用户可以做什么、自然的示例话术，以及对方积极回应、婉拒或暂未回应时的分支和应暂停的条件。计划按行动 id 缓存，重复打开不重复调用模型；点「重新生成」才按最新资料重写。

这是针对一条建议的一次性计划，不是常驻的 AI 教练，不做性格或关系分析，也不保存长期对话记忆。

## 换一批

两个入口，都是重新生成一版建议，区别只在范围：

- **区块标题旁的「换一批」**：重新生成今天的全部建议，避开当前正在显示的那些标题。
- **每条建议右侧的 ↻ 图标**：只换掉这一条，其余尽量保持——服务端把这条的标题作为 `avoid` 传下去。

模型经常把同一句话原样再给一遍，所以 `avoid` 会真的参与过滤。如果一条新的都没换出来，**保留原来那批**并在标题下提示「这次没换出新的建议」，不会把用户正在看的建议清空。标题里的空格和大小写不影响比对。

换一批同样遵守「没有社交目的不生成」：这类联系人点换一批不会调用模型，只显示未填目的的提示。手动强刷也不会。

## 接口

- `GET /api/daily-actions`：读取当日推荐和处理状态，不调用模型。返回含 `intervalPresets`（可选间隔基准）、每位联系人的 `interval` / `intervalDays`（实际间隔，已含客观信号修正）与 `gap`（距上次对话天数）。
- `POST /api/daily-actions/generate`：异步补齐当日推荐。参数：`contactName` 限定一位联系人；`force: true` 强刷一位（必须带 `contactName`）；`reshuffle: true` 换一批，可以不带 `contactName`，表示今天全部重来；`avoid` 是最多 4 个要避开的标题。
- `POST /api/daily-actions/:id/feedback`：设置 `status` 为 `pending`、`done` 或 `dismissed`。
- `POST /api/daily-actions/:id/plan`：生成或读取该行动的详细计划；`recreate: true` 强制按最新资料重写。

社交目的复用联系人的 `social_goal` 字段（联系人页已有入口），保存走 `POST /api/contacts/:name/profile` 的 `socialGoal`，不新增画像或关系档案。

新增表只存储这一功能的数据（`social_daily_batches`、`social_daily_actions`、`social_interval_state`、`social_daily_plan`），不迁移或覆盖原有聊天、联系人资料与日程。推荐复用现有统一模型引擎及配置，没有新增 Provider、密钥配置或独立模型服务。
